# 詳細設計書

## 1. はじめに

### 関連文書

関連する文書を記載する

### 用語定義

開発対象特有の用語を記載する。

## 2. 動作環境

システムの動作環境について、以下を記載する。

- ハードウェア
- OS
- ミドルウェア
- フレームワーク
- ライブラリ

## 3. 非機能要件の実現方針

[基本設計書](./functional-design.md)で定義した非機能要件について、以下を記載する。

- 非機能要件ID
- 要件概要
- 設計方針

## 4. アーキテクチャ

### 論理構造

対象の論理的な構造をコンポーネント図、クラス図などで定義する。

### 配置構造

ファイルの配置構造を記載する。

### 動的構造

対象のふるまいをシーケンス図などで定義する。

## 5. 機能

要件を実現するための機能を記載する。
以下を記載する。

- 要件ID
- 対応する機能

## 6. 設計方針

### データの設計方針

外部連携、DBテーブル、ファイル・メッセージ形式などを記載する。

### カスタマイズ・設定の設計方針

カスタマイズや設定の仕組みが必要な場合は、その方針を記載する。

### ログ出力の設計方針

ログ出力の仕組みが必要な場合は、その方針を記載する。

### エラー処理の設計方針

エラー発生時の共通的な処理の方針を記載する。

### インタフェースの設計方針

開発対象がコマンドの場合、以下を記載する。

- 命名
- 戻り値
- 引数
- 出力フォーマット

開発対象が GUI の場合、以下を記載する。

- 画面の基本構成
- 画面の遷移
- 利用者へのメッセージの示し方

## 7. その他・注意事項

補足事項や注意事項があれば記載する。
